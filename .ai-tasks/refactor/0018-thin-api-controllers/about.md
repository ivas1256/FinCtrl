# [0018] Тонкие API-контроллеры и DTO-контракт

- **Ветка:** `refactor/0018-thin-api-controllers`
- **Репозитории:** backend, frontend
- **Создана:** 2026-10-20
- **Источник:** `.ai-docs/project/architecture-audit.md`, §2.2, §2.3, §2.5; пункты, отложенные задачами 0015–0017

## Контекст
`PaymentsApiController` и `DashboardApiController` содержат бизнес-логику:
- поля-состояние (`_categoriesTree`, `_groupingType`);
- дефолтные периоды через `DateTime.Today`;
- фейковые категории;
- `BuildTree` и `ToPeriodKey`;
- проценты и `GetWeekStart`;
- правила правки платежа (`EditPayment`): правка и теги — две записи не в одной транзакции; при несуществующем теге платёж уже сохранён, а ответ 400.

Кроме того:
- наружу отдаются доменные сущности (`CategoriesApi`, `GetBySource`);
- маппинг `Payment → PaymentDto` продублирован и расходится (в `GET api/PaymentsApi/list` поле `paymentSource.createdAt` всегда `0001-01-01`);
- ответы — анонимные типы;
- в API строки `"on"` вместо `bool` (`ExcludeFromStatsStr`); PUT платежа без `description`/`excludeFromStatsStr` затирает описание и флаг;
- PUT/DELETE отвечают 200 вместо 204;
- магические id категорий (`33`, `int.MaxValue`, `int.MaxValue - 1`);
- `DateRange.To` трактуется по-разному, в `GET list` — даты `1753`/`9999`;
- `Payment` — мутабельный `record`;
- DTO лежат в технической папке `RequestDto/` (там же выходной `CategoryDto`);
- нет тестового проекта `FinCtrl.Website.Tests` для маппинга;
- в §10 `backend-guide.md` устарели пункты техдолга (NRE в `EditPayment` и т.п.).

## Постановка
- Перенести построение дерева/периодов/фейковых категорий/дефолтных периодов в Application (сервис статистики возвращает готовую read-модель), Dashboard-расчёты (проценты, дефолтные периоды графика) — в `DashboardService`, правила правки платежа — в `PaymentService.Edit(...)` под `IUnitOfWork` (правка + теги атомарно, проверки до записи).
- Контроллеры без состояния в полях; один маппинг на пару типов; DTO вместо доменных сущностей; именованные `*Response` вместо анонимных типов; `NoContent()` для PUT/DELETE (frontend не должен зависеть от 200).
- Константы id категорий («Накопления», фейковые) в Domain; единая (исключающая) семантика `DateRange.To`, убрать `1753`/`9999`.
- `bool` вместо `"on"`-строк в JSON-API с согласованной правкой frontend; для `ExcludeFromStats` и `Description` — null = не трогать.
- `Payment`: `record` → `class`.
- DTO разложить по `Controllers/<Feature>Api/`, один публичный тип на файл; убрать `RequestDto/`.
- Тестовый проект `FinCtrl.Website.Tests` для маппинга DTO.

## Вне объёма
- Изменение URL существующих маршрутов.
- Legacy-семантика `CategoryId` в правке платежа (null — не трогать, очистить нельзя).
