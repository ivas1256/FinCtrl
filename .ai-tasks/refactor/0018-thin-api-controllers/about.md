# [0018] Тонкие API-контроллеры и DTO-контракт

- **Ветка:** `refactor/0018-thin-api-controllers`
- **Репозитории:** backend, frontend
- **Создана:** 2026-10-20
- **Источник:** `.ai-docs/project/architecture-audit.md`, §2.2, §2.3, §2.5

## Контекст
`PaymentsApiController` и `DashboardApiController` содержат бизнес-логику:
- поля-состояние;
- дефолтные периоды через `DateTime.Today`;
- фейковые категории;
- `BuildTree` и `ToPeriodKey`;
- проценты и `GetWeekStart`;
- правила правки платежа.

Кроме того:
- наружу отдаются доменные сущности (`CategoriesApi`, `GetBySource`);
- маппинг `Payment → PaymentDto` продублирован и расходится;
- ответы — анонимные типы;
- в API строки `"on"` вместо `bool`;
- магические id категорий;
- `DateRange.To` трактуется по-разному;
- `Payment` — мутабельный `record`;
- DTO лежат в технической папке `RequestDto/`.

## Постановка
- Перенести построение дерева/периодов/фейковых категорий/дефолтных периодов в Application (сервис статистики возвращает готовую read-модель), Dashboard-расчёты — в `DashboardService`, правила правки платежа — в `PaymentService.Edit(...)`.
- Контроллеры без состояния в полях; один маппинг на пару типов; DTO вместо доменных сущностей; именованные `*Response` вместо анонимных типов; `NoContent()` для PUT/DELETE.
- Константы id категорий («Накопления», фейковые) в Domain; единая (исключающая) семантика `DateRange.To`, убрать `1753`/`9999`.
- `bool` вместо `"on"`-строк в JSON-API с обратной совместимостью или согласованной правкой frontend; для `ExcludeFromStats` — null = не трогать.
- `Payment`: `record` → `class`.
- DTO разложить по `Controllers/<Feature>Api/`, один публичный тип на файл; убрать `RequestDto/`.

## Вне объёма
- Изменение URL существующих маршрутов.
