# [0017] Обработка ошибок и валидация по гайду

- **Ветка:** `refactor/0017-errors-validation`
- **Репозитории:** backend, frontend
- **Создана:** 2026-10-20
- **Источник:** `.ai-docs/project/architecture-audit.md`, §2.3, §2.5

## Контекст
Нет глобального обработчика ошибок, есть только `UseDeveloperExceptionPage`. Из-за этого:
- несуществующий id в `EditPayment` даёт NRE и 500;
- `Update` у Accounts/Tags/PaymentSources для несуществующего id возвращает 200.

Ошибки ввода сигнализируются через `NotImplementedException`. Проверки уникальности стоят в контроллерах, а не в сервисах. Перед Delete не проверяются связи, поэтому срабатывает FK и пользователь получает 500. DataAnnotations нет.

## Постановка
- В Application: `NotFoundException`, `ValidationException` (и `ConflictException` при необходимости).
- В Website: глобальный обработчик → ProblemDetails (404/400/409), `AddProblemDetails`.
- Перенести проверки уникальности и обязательности из `AccountsApi`/`TagsApi` в сервисы.
- Проверка связей перед удалением категории/счёта (понятная ошибка вместо 500).
- Заменить `NotImplementedException` для формата файла и группировки на `ValidationException`.
- DataAnnotations на входных DTO; явные null-контракты сервисов (`Get` → NotFound).
- Frontend: показывать `title`/`detail` из ProblemDetails там, где сейчас показывается текст ошибки.

- Ошибки, отложенные предыдущими задачами (0005–0016): `GET api/PaymentsApi` без `periodType` → 500 `NotImplementedException`; правка несуществующего источника → 204/200; несуществующая категория источника / тег платежа → 500 на FK; `CsvFileFormat` зависит от текущей культуры (`-55.5` на ru-RU → 500), CSV только с заголовком без перевода строки падает; SQL-ошибки и исключения отдаются страницей исключения.

## Вне объёма
- Перенос логики из контроллеров (0018), в т.ч. атомарность `EditPayment` и семантика null в `PaymentEditDto`.
- Производительность `GET api/PaymentsApi/list` без `pageSize` (все записи).

## Критерии приемки
- [ ] PUT/DELETE несуществующего id → 404 ProblemDetails во всех API
- [ ] Дубликат имени счёта/тега → 400/409 из сервиса
- [ ] Удаление категории/счёта со связями → понятная ошибка, не 500
- [ ] Неизвестный формат файла и некорректное содержимое файла → 400
- [ ] CSV разбирается независимо от текущей культуры; файл только с заголовком не падает
- [ ] `GET api/PaymentsApi` без группировки → 400, а не 500
- [ ] Несуществующая категория источника / тег, категория, счёт платежа → 400, а не 500 на FK
- [ ] Непредвиденные ошибки → 500 ProblemDetails, без страницы исключения
- [ ] Юнит-тесты сервисов на эти сценарии
- [ ] Frontend показывает сообщения ошибок
- [ ] Сборка затронутых частей проходит без ошибок, нет новых предупреждений в изменённых файлах
- [ ] Все тесты зелёные
