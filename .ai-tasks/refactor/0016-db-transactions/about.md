# [0016] Транзакции, N+1 и доменные правила вне Infrastructure

- **Ветка:** `refactor/0016-db-transactions`
- **Репозитории:** backend
- **Создана:** 2026-10-20
- **Источник:** `.ai-docs/project/architecture-audit.md`, §2.3, §2.4

## Контекст
Транзакций нет и открыть их негде: `IDbConnectionFactory` это не поддерживает. Поэтому многошаговые записи выполняются без атомарности:
- `SetPaymentTags` (DELETE + INSERT);
- `TagRepository.Delete` (сначала связи, потом тег);
- импорт: при падении на N-й строке первые N-1 строк уже записаны.

Кроме того:
- дерево категорий строится рекурсивными запросами (N+1);
- знак суммы правится в `Infrastructure/Payments/PaymentDto.cs:66-69`;
- `FindDuplicate` читает с `WITH (NOLOCK)`;
- импорт без логов и без `CancellationToken`.

## Постановка
- Ввести поддержку транзакций (unit-of-work или `BeginTransaction` в фабрике соединений с передачей транзакции в репозитории).
- Транзакции в `SetPaymentTags`, `TagRepository.Delete`, импорте.
- Дерево категорий: один запрос + сборка дерева в памяти.
- Знак суммы — доменное правило в `Payment` (Domain), не в маппере.
- Убрать `NOLOCK` в выборках для поиска дублей.
- Импорт: `ILogger` (создано/дозаполнено/пропущено) и `CancellationToken`; сократить число запросов на строку.
