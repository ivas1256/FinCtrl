# [0041] Перенести БД с MS SQL Server на PostgreSQL

- **Ветка:** `chore/0041-migrate-to-postgres`
- **Репозитории:** backend `FinCtrl/`
- **Создана:** 2026-11-15

## Контекст
Пользователь переводит хранилище FinCtrl с MS SQL Server на PostgreSQL. Подход согласован в чате 2026-11-15.

## Постановка
- Схема БД — новый baseline под PostgreSQL (итог миграций 0001–0006; 0007 — только данные). Старые T-SQL-миграции — архив `db/migrations-mssql/`.
- Имена таблиц и колонок без кавычек: PostgreSQL приводит их к нижнему регистру, SQL в C# остаётся PascalCase, Dapper маппит колонки без учёта регистра.
- Типы: `INT IDENTITY` → `GENERATED BY DEFAULT AS IDENTITY`, `NVARCHAR` → `text`/`varchar(n)`, `DATETIME2` → `timestamp`, `BIT` → `boolean`, `DECIMAL(18,2)` → `numeric(18,2)`; фильтрованные уникальные индексы → частичные.
- Backend: `Microsoft.Data.SqlClient` → `Npgsql`; SQL: `OUTPUT INSERTED` → `RETURNING`, `TOP` → `LIMIT`, флаги `= 0/1` → `false/true`, без `dbo.`, `IN @Ids` → `= ANY(@Ids)` (разбивка на пачки из-за лимита 2100 параметров больше не нужна).
- Одноразовый скрипт переноса данных из SQL Server (`FinCtrl_db_dev2`, `FinCtrl_db`) в PostgreSQL с сохранением id, сдвигом identity и сверкой.
- Документация: `CLAUDE.md`, `project-summary.md`, `backend-guide.md`, README миграций.

## Вне объёма
- Сравнение строк — по умолчанию PostgreSQL (с учётом регистра); `citext`, `lower()`-индексы, ICU-collation не делаем (решение пользователя).
- Базы SQL Server не меняются и не удаляются.
- `appsettings.Production.json` не меняется (его правку блокирует хук): строку подключения для Production пользователь задаёт сам (переменная окружения `ConnectionStrings__DefaultDatabase` или правка файла вне PR).
- Интеграционные тесты на реальной БД.
