# [0002] Хук проверки перед PR (Definition of Done)

- **Ветка:** `chore/0002-pre-pr-hook`
- **Репозитории:** инструменты Claude Code (`.claude/`), регламент (`.ai-docs/workflow/`)
- **Создана:** 2026-10-19

## Контекст
Раздел 4 регламента («Проверка перед PR») держится только на дисциплине агента. Механическую часть нужно выполнять принудительно хуком при `git push` / `gh pr create`, а пункты, требующие суждения, оставить ручными.

## Постановка
- `PreToolUse`-хук Claude Code (`.claude/settings.json` + `.claude/hooks/pre-pr-check.mjs`) на команды `git push` / `gh pr create` в Bash/PowerShell.
- Хук проверяет: git-предусловия (не `main`, имя ветки по шаблону, чистое дерево, нет `--force`/`--no-verify`), строку задачи в журнале, отсутствие неотмеченных критериев в `about.md`, сборку и тесты затронутых частей, предупреждения сборки в изменённых файлах, гигиену диффа (отладочный код, артефакты, секреты, отключённые/удалённые тесты).
- При провале — блокирует команду (exit 2) с отчётом; при успехе кэширует результат по SHA `HEAD`.
- Регламент (раздел 4) размечен: что проверяет хук, что остаётся ручным.

## Вне объёма
- Ручная проверка в preview, смысловая проверка критериев и соответствия диффа задаче, решение об обновлении документации — остаются за агентом.
- Git-хуки (`pre-push`) для ручных push'ей пользователя.
- Создание тестовой инфраструктуры.

## Критерии приемки
- [x] Команды без `git push`/`gh pr create` не замедляются (хук выходит сразу)
- [x] `git push` с `main` или с грязным деревом блокируется с понятным сообщением
- [x] Отладочный `console.log` в диффе блокирует push
- [x] Неотмеченный пункт в `about.md` блокирует push
- [x] Чистая ветка проходит; повторный вызов на том же `HEAD` берётся из кэша
- [x] Раздел 4 регламента и `CLAUDE.md` описывают хук
