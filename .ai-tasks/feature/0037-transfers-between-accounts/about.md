# [0037] Переводы между своими счетами

- **Ветка:** `feature/0037-transfers-between-accounts`
- **Репозитории:** backend `FinCtrl/` + frontend `FinCtrl.Frontend/`
- **Создана:** 2026-11-06

## Контекст
Переводы между своими счетами (карта → вклад, вклад → карта и т.п.) сейчас попадают в траты и доходы и искажают аналитику. Нужно уметь отмечать такие операции переводом, связывать две стороны и исключать их из трат/доходов.

## Постановка
Работа идёт в 4 этапа в одной ветке, каждый этап согласуется отдельно.

1. **Схема БД.** Миграция `0005_transfers.sql`: `Accounts.IsSavings`, таблица `Transfers` (`OutPaymentId` — списание, `InPaymentId` — поступление или `NULL`, без каскада), уникальный фильтрованный индекс `UQ_Payments_Account_Date_Sum` против дублей. `PaymentTypeEnum.Transfer = 2` вместо мёртвых `InvoiceTransfer`/`CardTransfer`. Domain `Transfer`, `ITransferRepository`, поля `TransferId`/`TransferPairPaymentId` в `SelectPayment` и обоих `PaymentDto`. Флажок «Накопительный» на странице «Счета».
2. **Импорт.** `FindDuplicate` ищет по `AccountId + PaymentDate + PaymentSum`; без счёта — по сумме и дате с дозаполнением счёта (как раньше). У найденного дубля `PaymentType` не трогается.
3. **Модалка правки платежа (главная).** `EditPaymentRequest.IsTransfer` / `TransferPairPaymentId` (null = не трогать, `0` = отвязать), валидация 400/409, вторая сторона тоже `Transfer`, одна транзакция. `GET api/PaymentsApi/{id}/transfer-candidates`. Галочка «Перевод между своими счетами», select «Вторая сторона», автоподстановка «Накоплений», если счёт второй стороны накопительный (чистая функция + Vitest).
4. **Аналитика.** Фейковая категория `FakeTransfers` / строка «Переводы» на главной, не входит в «ВСЕГО»; переводы с категорией «Накопления» остаются в «Накоплениях». Дашборд: `FilterSpendings` исключает `Transfer`.

## Решения
- Две одинаковые строки (счёт + дата + сумма) в одном файле: вторая находится `FindDuplicate` как дубль первой и тихо пропускается, ошибки нет. Уникальный индекс защищает целостность БД (гонки, ручные вставки, обход дедупликации), а не сообщает о повторах в файле.
- Уникальность `Transfers.InPaymentId` — фильтрованным индексом `WHERE InPaymentId IS NOT NULL`: обычный `UNIQUE` в SQL Server допускает только один `NULL`.
