# [0032] Карточка сравнения: расчёт строк, топ-3 и полос

- **Ветка:** `feature/0032-comparison-card-rows`
- **Репозитории:** frontend
- **Создана:** 2026-10-23
- **Источник:** `.ai-docs/project/payments-table-month-comparison-requirements.md` (далее СР) §4.4–4.5, §4.7, §5.3, §7; критерии СР 25–30, 37
- **Зависит от:** 0027 (`periodComparison.js`), 0031 (карточка)

## Контекст
Карточка сравнения (0031) показывает сводку по категории. Чтобы разобрать изменение по подкатегориям, нужны строки таблицы карточки, топ-3 роста/снижения, сортировка и масштаб полос. По СР §5.1 это представление считается на фронтенде в чистых функциях, компоненты только вызывают их. Задача — только расчёт с тестами, без UI (UI — 0033).

## Постановка
Чистые функции в `src/utils/periodComparison.js` (или новом `src/utils/comparisonCard.js`) на входе — узел дерева ответа `GET api/PaymentsApi` (охват) или корень дерева («Итого»), на выходе — модель строк карточки:
- **Строки охвата-категории** (СР §4.5): дети узла в порядке дерева, у каждого — свои дети (внуки) рекурсивно; плюс строка «{Имя} (без подкатегории)» с `own(p, m) = v(p, m) − Σ v(c, m)`, если `own ≠ 0` хотя бы в одном периоде. Каждая строка: имя, уровень, S_П, S_Т, результат `compare` (Δ₽, Δ%, состояние), стрелка/тон как у `deltaCellView`, признак служебной строки.
- **Строки охвата «Итого»** (СР §4.5): корневые категории трат (без доходных, «Накоплений», «ВСЕГО»), затем «Без категории» (служебная).
- Строки с S_П = 0 и S_Т = 0 не включаются.
- **Топ-3** (СР §4.4): по непосредственным строкам охвата; рост — Δ₽ > 0 по убыванию Δ₽, снижение — Δ₽ < 0 по возрастанию; при равенстве — по |Δ%| убыв., затем по имени; меньше трёх — сколько есть.
- **Сортировка** (СР §4.5): «По категориям» — порядок дерева, служебные строки в конце; «По изменению» — по убыванию Δ₽ на каждом уровне (внуки — внутри своего родителя), «новые» — как обычный рост.
- **Масштаб полос** (СР §4.5): `M = max |Δ₽|` по всем строкам, включая внуков; доля полосы `|Δ₽| / M` (0..1), при `M = 0` — 0 у всех.
- Охват-лист (нет детей) — признак «нет подкатегорий», строк и топ-3 нет (СР §4.7). Если у всех детей S_П = S_Т = 0 — единственная строка «(без подкатегории)» (СР §4.7).

## Решения исполнителя (неблокирующие)
- Расчёт карточки — на фронтенде, backend и новый эндпоинт не нужны: все входы (`comparison.current/previous` у каждого узла дерева) уже есть в ответе `GET api/PaymentsApi`. Обоснование и границы решения — СР §5.1, абзац «Карточка сравнения»; отклонённый вариант — СР §5.4.
- Семантика строк (`Semantics`) наследуется от охвата: в карточке доходной категории подстроки считаются как доход, в карточке «Накоплений» — как «Накопления» (как `getSemantics` с `inSavings`).
- `own ≠ 0` проверяется с допуском полкопейки (|own| ≥ 0.005), чтобы погрешность сумм с плавающей точкой не давала пустую строку «(без подкатегории)».
- Строка «(без подкатегории)» есть и у внуков-родителей (на любом уровне), чтобы сумма строк каждого уровня сходилась с родителем.
- «Без категории» в охвате «Итого» участвует в топ-3 и в сортировке «По изменению» как обычная строка (СР §4.4: кандидаты — непосредственные строки таблицы; критерий 28 ставит её в середину сортировки). В топ-3 критерия 26 она не попадает по величине (+700).
- Сортировка возвращает новый массив, исходная модель не мутируется.

## Вне объёма
- Вёрстка таблицы, полос, топ-3, переключатель сортировки — 0033.
- Изменения backend.
