# [0035] FinCtrl.AiAssistant: API классификации источников платежей

- **Ветка:** `feature/0035-ai-assistant-classify-api`
- **Репозитории:** `FinCtrl.AiAssistant/` (Python, FastAPI)
- **Создана:** 2026-11-03

## Контекст
`FinCtrl.AiAssistant/` был одноразовым скриптом: API-ключ LLM-прокси зашит в код, при импорте модуль читал `payment-sources.json` и печатал сырой ответ модели, ответ не проверялся, ошибки уходили в `print`. Нужно превратить его в сервис, который backend сможет вызывать для классификации источников платежей.

## Постановка
1. API-ключ (и адрес/модель LLM) — из переменных окружения / `.env`.
2. Эндпоинт `POST /payment-sources/classify`: принимает список `PaymentSource` (`Id`, `Name`), возвращает ответ LLM — список `ClassifiedPaymentSource` (`Id`, `Name`, `Classification`).
3. Валидация ответа LLM: корректный JSON, схема, Id ровно те же, что во входе, без дублей, непустая `Classification`.
4. Отправка запроса к LLM — в отдельном классе `LlmClient`.
5. Логирование всех ошибок в файл.
6. При любой ошибке на стороне сервиса (LLM недоступна, невалидный ответ, непредвиденное исключение) — ответ 500.

## Вне объёма
- Интеграция с backend FinCtrl (вызов сервиса из .NET, сохранение классификации в БД).
- Изменение промта по содержанию (меняется только формат ответа — см. журнал решений в `plan.md`).
- Автотесты на Python (решение пользователя).

## Критерии приемки
- [x] В коде нет API-ключа; без `LLM_API_KEY` сервис не стартует с понятной ошибкой
- [x] `POST /payment-sources/classify` со списком источников → 200 и список с `Classification` для каждого Id
- [x] Пустой список → `[]` без обращения к LLM; невалидное тело → 422
- [x] Невалидный ответ LLM (не JSON, не те Id, пустая классификация) → 500
- [x] Ошибка LLM (неверный ключ, сеть, лимиты) → 500, запись с трейсом в `logs/errors.log`
- [x] Запрос к LLM вынесен в класс `LlmClient`
