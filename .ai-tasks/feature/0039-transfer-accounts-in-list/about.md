# [0039] Счета перевода в списке операций на главной

- **Ветка:** `feature/0039-transfer-accounts-in-list`
- **Репозитории:** backend `FinCtrl/`, frontend `FinCtrl.Frontend/`
- **Создана:** 2026-11-07

## Контекст
На главной (тепловая карта `PaymentsTable.vue`) клик по ячейке открывает список операций (`PaymentList.vue`). В строке «Переводы» сейчас не видно, с какого счёта на какой перевели деньги. Список вообще не показывает счета, хотя `payment.account` в данных есть. Id второй стороны перевода у платежа есть (`transferPairPaymentId`), а её счёта нет: `SelectPayment` соединяет платёж с `Transfers`, но не подтягивает платёж второй стороны и его счёт.

Искать вторую сторону среди уже загруженных платежей на frontend ненадёжно. Она может оказаться в другом периоде, вне выбранного диапазона, в «Накоплениях» или отсеяться фильтром по тегам. Поэтому счёт второй стороны отдаёт backend.

## Постановка
- Backend отдаёт у каждого платежа счёт второй стороны перевода: поле `transferPairAccount` (или `null`, если пары нет или у второй стороны нет счёта).
- В списке операций под ячейкой у перевода выводится строка «Счёт A → Счёт B»:
  - у списания A — свой счёт, B — счёт второй стороны;
  - у поступления A — счёт второй стороны, B — свой счёт;
  - если пары нет или у стороны нет счёта — вместо названия «не указан».
- Попутно: в модалке правки поле «Вторая сторона» вместо «Связанная операция #id» (когда пары нет среди кандидатов) показывает счёт второй стороны.

## Вне объёма
- Показ счёта у обычных (не переводных) операций в списке.
- Изменение того, какие переводы попадают в строку «Переводы», и расчёта сумм.
- Миграции БД — не нужны.

## Критерии приемки
- [ ] `GET /api/PaymentsApi` у связанного перевода возвращает `transferPairAccount` со счётом второй стороны; у перевода без пары и у обычного платежа — `null`
- [ ] Клик по ячейке «Переводы» → у списания строка «<свой счёт> → <счёт второй стороны>», у поступления — наоборот
- [ ] У перевода без пары или без счёта вместо названия выводится «не указан»
- [ ] В модалке правки текущая вторая сторона, не найденная среди кандидатов, подписана с её счётом
- [ ] Сборка проходит без ошибок
- [ ] Все тесты зелёные, на новую логику написаны юнит-тесты
