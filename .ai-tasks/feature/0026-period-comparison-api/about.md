# [0026] Сравнение с прошлым периодом: суммы Т и П в API таблицы

- **Ветка:** `feature/0026-period-comparison-api`
- **Репозитории:** backend
- **Создана:** 2026-10-23
- **Источник:** `.ai-docs/project/payments-table-month-comparison-requirements.md` (далее СР) §2.1, §2.2, §5.1, §5.2; ДТ §5.7

## Контекст
На главной нужна колонка изменения трат к прошлому периоду для любой группировки. Прошлый период часто лежит вне фильтра дат, а ключи периодов (особенно номер недели) считаются по правилам .NET — поэтому границы и суммы считает бэкенд, а Δ — фронтенд (гибридная схема, СР §5.1).

## Постановка
- `MainStatisticService.GetPaymentsTable` определяет `D = min(сегодня по TimeProvider, «по» − 1 день)`, текущий период Т (период группировки, содержащий D, от начала по D включительно) и прошлый период П (предыдущий целиком).
- Для каждого узла дерева — знаковые суммы за Т и П (родитель включает потомков, теги учитываются, «ВСЕГО» и «Без категории» — по тем же правилам, что ячейки).
- Ответ `GET api/PaymentsApi` расширяется: в узле `comparison: { current, previous }`, в корне `comparison: { asOf, current {key, from, to}, previous {key, from, to}, currentPeriodTo, isCurrentPartial }` (форма — СР §5.2).
- Если Т пересекается с фильтром, но платежей в нём нет, Т добавляется в `periods` (пустые ячейки).

## Вне объёма
- Расчёт Δ₽/Δ%, подписи, отображение — задачи 0027, 0028.
- Отдельный эндпоинт сравнения (отклонён, СР §5.4).

## Критерии приемки
- [ ] Ответ содержит блок `comparison` при любой группировке (день/неделя/месяц/квартал/год) и любом диапазоне дат
- [ ] Границы Т/П верны для всех группировок, в т.ч. на переходе года (неделя 29.12–04.01, январь → декабрь, I кв. → IV кв.)
- [ ] D = последний день периода → `isCurrentPartial = false`; «по» в прошлом → D = «по»
- [ ] П вне фильтра дат — суммы П всё равно посчитаны
- [ ] Суммы родителя включают потомков, теги фильтруют суммы, «ВСЕГО» не включает «Без категории»
- [ ] Т без платежей, пересекающийся с фильтром, есть в `periods`
- [ ] Сборка проходит без ошибок
- [ ] Все тесты зелёные, на новую логику написаны юнит-тесты (`FakeTimeProvider`)
