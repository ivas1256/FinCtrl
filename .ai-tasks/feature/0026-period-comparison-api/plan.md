| Что тестируем | Сценарии |
|---------------|----------|
| Границы Т/П | 5 группировок; переход года для недели/месяца/квартала/года; D — последний день периода; «по» в прошлом; без диапазона (дефолт) |

## Ручная проверка
Swagger / Network на dev-базе: группировки месяц и неделя, суммы П за прошлый месяц сверить с отчётом на странице «Операции».

## Риски и открытые вопросы
- Объём выборки при группировке «Год»: П — весь прошлый год. Для личного приложения допустимо.
- Решения исполнителя по СР-О13 (см. журнал): Т — период, содержащий D = min(сегодня, «по»); Т — с начала периода, даже если «с» внутри Т.

## Журнал решений
- 2026-10-23: задача заведена по декомпозиции ДТ/СР. СР-О13 решён исполнителем по рекомендации документа (неблокирующий вопрос, правило пользователя).
- 2026-10-23 (шаг 3): суммы сравнения — **отдельным вызовом** `Calculate` за `[начало П, D + 1)` с теми же тегами, а не одной выборкой по объединённому диапазону: ячейки таблицы не меняются, П вне фильтра не попадает в `periods`; цена — второй запрос к БД.
- 2026-10-23: `PaymentsTable.Comparison`/`PaymentsTableNode.Comparison` и их DTO — nullable (сервис заполняет всегда; `null` только у вручную собранной модели), чтобы фронтенд мог проверять наличие блока (СР §2.2).
- 2026-10-23: Т добавляется в `periods` полным периодом `[начало, конец периода)` (как остальные колонки), если пересекается с фильтром; при фильтре целиком в будущем (D = сегодня до «с») Т вне фильтра — не добавляется.
- 2026-10-23: в тестах мок `GetByDateRange` фильтрует платежи по диапазону, а таблица в старых тестах строится по `TableRange` (2026 г.), не пересекающемуся с «сегодня» 15.10.2025, — иначе к ожидаемым `periods` добавлялся бы Т.
