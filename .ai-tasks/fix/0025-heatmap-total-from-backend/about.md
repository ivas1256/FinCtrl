# [0025] Главная: «Итого» из бэкенда, без двойного учёта «ВСЕГО»

- **Ветка:** `fix/0025-heatmap-total-from-backend`
- **Репозитории:** frontend
- **Создана:** 2026-10-23
- **Источник:** ДТ §3.2, §5.5, §7, Р9; решение В3 (= О3 документа сравнения)

## Контекст
Сейчас строка «ВСЕГО потрачено:» (`CategoryIds.FakeTotal`) показывается в теле таблицы с теплом, а `tfoot` «Итого» — сумма всех корней на фронте (`periodTotal`), включая доходы, «Без категории» и саму «ВСЕГО». Итог задваивается, а «ВСЕГО» забирает максимум тепловой шкалы — остальные категории бледные.

## Постановка
- «Итого» в `tfoot` берёт значения из узла «ВСЕГО» (`FakeTotal`), посчитанного бэкендом; `periodTotal` (сумма корней) удалить.
- Узел «ВСЕГО» не выводится в теле таблицы и не участвует в `computeMaxValue`.
- Пустое состояние «Нет данных» — если у всех узлов (кроме «ВСЕГО») нет сумм ни в одном периоде.
- Под таблицей — сноска: «Без категории» не входит в «Итого».

## Вне объёма
- Изменение расчёта «ВСЕГО» на бэкенде.
- Колонка Δ в «Итого» — задача 0028.

## Критерии приемки
- [ ] Строки «ВСЕГО потрачено:» в теле таблицы нет
- [ ] «Итого» по каждому периоду равно значению узла «ВСЕГО» из ответа API (сверка на dev-базе)
- [ ] Максимум тепловой шкалы считается без «ВСЕГО» — у самой крупной категории самое насыщенное тепло
- [ ] При выборке без платежей показывается «Нет данных»
- [ ] Под таблицей есть сноска про «Без категории»
- [ ] Сборка проходит без ошибок
- [ ] Все тесты зелёные, на новую логику написаны юнит-тесты (сначала красный тест на двойной учёт)
