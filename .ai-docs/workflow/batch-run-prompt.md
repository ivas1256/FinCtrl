# Промт пакетного запуска задач

Как это устроено — `task-workflow.md`, раздел 8.

## Как запустить

1. Рабочее дерево чистое, `main` актуален (`git checkout main && git pull --ff-only`).
2. Новая сессия в Claude desktop (вкладка Code), в корне репозитория. Модель — **Opus**, effort — **high**, режим — **auto**. Модель оркестратора — потолок для сессий-исполнителей, а сам он тратит мало: на каждую задачу у него один короткий ход.
3. Вставить промт ниже, при необходимости поправив таблицу задач.
4. Если пакет встал без ошибки (приложение перестаёт будить оркестратор после долгой серии автоматических ходов), написать в чат «продолжай».
5. Мёржить PR по порядку, начиная с первого, с удалением ветки.

## Промт

```
Ты — оркестратор пакетного запуска задач (регламент .ai-docs/workflow/task-workflow.md, раздел 8). Сам код не пишешь и файлы задач не читаешь — только запускаешь и проверяешь.

Задачи по порядку (ID — модель — effort):
1. 0024 — claude-sonnet-5-5 — medium
2. 0025 — claude-sonnet-5-5 — medium
3. 0026 — claude-opus-5-5 — high
4. 0027 — claude-sonnet-5-5 — medium
5. 0028 — claude-opus-5-5 — high
6. 0029 — claude-sonnet-5-5 — medium
7. 0030 — claude-sonnet-5-5 — medium

Я разрешаю запустить все эти сессии сейчас, по одной, без подтверждения каждой.

Для каждой задачи по очереди:
1. Запусти отдельную сессию: start_session с initiation "user_asked", context "fresh", use_worktree false, permission_mode "auto", wake_when_done true, model и effort из таблицы, name "task-<ID>".
   prompt: «Выполни задачу <ID> из журнала .ai-tasks/tasks.md строго по регламенту .ai-docs/workflow/task-workflow.md, от старта до создания PR. Это пакетный запуск (раздел 8): создай ветку задачи от ветки <ПРЕДЫДУЩАЯ ВЕТКА>, PR открой в <ПРЕДЫДУЩАЯ ВЕТКА>. Скриншоты запрещены (раздел 4, п. 3). Неблокирующие вопросы решай сам и фиксируй решение в about.md/plan.md. Если задачу невозможно довести до PR — остановись и последним сообщением напиши СТОП: <причина>.»
   Для первой задачи <ПРЕДЫДУЩАЯ ВЕТКА> = main, дальше — ветка предыдущей задачи из колонки «Ветка» журнала.
   background: «Пакет задач 0024–0030 (тепловая карта главной и сравнение периодов) выполняется автономно, по одной сессии на задачу, стеком веток: каждая следующая строится на предыдущей, PR не мёржатся до конца пакета.»
2. Жди уведомления о завершении сессии. Не опрашивай её и не пиши ей.
3. Проверь сам, коротко: `git branch --show-current` совпадает с веткой задачи, `git status --porcelain` пуст, `gh pr list --head <ветка> --json url,baseRefName` вернул PR с нужной базой, в журнале у задачи статус «на ревью».
4. Всё сходится — одна строка в чат («0024 — PR <ссылка>») и следующая задача. Не сходится или сессия написала СТОП — останови пакет и сообщи, на какой задаче и почему; следующие не запускай.

В конце выведи таблицу: ID, ветка, PR, база PR — и порядок мёржа.
```
