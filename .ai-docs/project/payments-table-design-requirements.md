### 3.2. Тепловая шкала (как реализовано в `src/utils/heatmap.js`)

- Базовый цвет: `rgb(200, 76, 78)` = `#c84c4e` (красный = расходы, ТК §11 запрещает менять).
- `heatAlpha(v, maxV)`: `0`, если `v` пусто/0, `v > 0` (поступление) или `maxV = 0`; иначе `0.04 + |v| / maxV × 0.32` → диапазон **0.04–0.36**. Строка стиля: `background: rgba(200, 76, 78, α.toFixed(2))`.
- Опорные точки (на белом): α 0.04 → `#fdf8f8`; α 0.2064 (порог `hm-hi`, |v|/maxV = 0.52) → `#f4dada`; α 0.36 → `#ebbfbf`.
- `maxV = computeMaxValue(tree)` — максимум `|totalSum|` по всем узлам дерева (родители и дети), пересчёт при каждой загрузке.
- **Важно:** ТК §3 описывает старую формулу (0.06 + …×0.70, до 0.76) и старую легенду; актуальна формула из `heatmap.js`. Макет использует третью (`rgba(220,53,69, 0.06 + 0.44·v/max)`) — **не принимаем**, только эскиз (Р3).
- **[решено, В3]** строка «ВСЕГО потрачено:» (`CategoryIds.FakeTotal`) показывается только как «Итого» в `tfoot`; из тела таблицы она убирается и из `maxV`/тепловой шкалы исключается. Это **следствие** решения «итог считаем на бэке» (иначе «ВСЕГО» почти всегда даёт максимум и все категории бледные, и сумма учитывается дважды) (Р9).
- Легенда в шапке: градиент `linear-gradient(to right, rgba(200,76,78,0.07), rgba(200,76,78,0.78))` 72×7px, радиус 4px **[есть]** — не совпадает со шкалой. **[предложение]** привести к `rgba(200,76,78,0.04)` → `rgba(200,76,78,0.36)`.

- Макет показывает целые рубли и минус U+2212 («−24 650 ₽») — расхождение Р8. **[решено, В2]** в ячейках периодов и «Итого» остаются копейки и `formatSignedCurrency` без изменений.

### 5.7. Правила расчёта Δ (новое из макета A, нужно для отображения)
Источник истины — документ сравнения (§2.1, §5); здесь — сводка. **[решено 2026-10-23]**
- Работает для **любой** группировки (месяц, неделя, квартал, год, день). Сравниваются **текущий период Т** — период группировки, содержащий `D = min(сегодня, «по»)`, от его начала по D — и **прошлый период П** — предыдущий период группировки **целиком**. Не «последний против предпоследнего периода выборки»: П может лежать вне фильтра дат, а колонки периодов без платежей бэкенд не возвращает.
- **Где считается (гибрид):** бэкенд (`MainStatisticService`) определяет D, границы и ключи Т/П и отдаёт для каждого узла дерева знаковые суммы за Т и П (родитель включает потомков, теги учитываются, «Итого» — узел «ВСЕГО», В3) в блоке `comparison` ответа `GET api/PaymentsApi`; фронтенд считает Δ₽, Δ%, состояния и всё отображение в чистой утилите (документ сравнения §5.2–§5.3). Фронтенд не вычисляет «сегодня» и ключи периодов.
- Для расходов: `Δ = |Т| − |П|` (рост трат > 0 → ▲ красный). `Δ% = round(Δ / |П| × 100)`; если прошлая сумма отрицательна (возвраты > трат), знаменатель всё равно `|П|` — знак процента совпадает со знаком Δ (подробнее — документ сравнения §5.3).
- `П = 0`, `Т ≠ 0` → Δ, ₽ как обычно, Δ, % = «новая». Оба 0 → «—», цвет `#6c757d`.
- Т неполный (`comparison.isCurrentPartial`) — подпись под таблицей: «Δ — {Т} по {D} против всего {П}» [макет], формулировки для каждой группировки — документ сравнения §2.1; плюс строка-легенда «▲ красным — тратите больше, ▼ зелёным — меньше. «новая» — в прошлом периоде трат не было.»
- **[решено, В6]** Строки с поступлениями (доходные категории) и «Накопления» **не** прочёркиваются целиком: Δ считается по тем же формулам; «—» только когда данных нет (нет сумм в обоих сравниваемых периодах). «Без категории» считается как обычная категория. Цвет Δ для доходных строк — открытый вопрос В12. «ВСЕГО» в теле таблицы больше нет — только «Итого» в `tfoot` (§5.5, В3).

## 10. Принятые решения (2026-10-23)

- **В3 → «Итого» считает бэкенд.** Решение: строку «Итого» (и её Δ) берём из «ВСЕГО потрачено» (`CategoryIds.FakeTotal`), посчитанного на бэке, а не суммой видимых строк на фронте. «Без категории» в итог бэкенда не входит — сноска сохраняется. Следствие (вытекает из решения, отдельно не обсуждалось): «ВСЕГО» убирается из тела таблицы и из `maxV` тепловой шкалы — нет двойного учёта. Затронуто: §3.2, §5.5, §5.7, §7, Р3, Р9.

- **В5 → зелёный для снижения разрешён.** Решение: `#146c43` с `▼` допустим в колонке сравнения и карточке. Следствие: в ТК §11 нужно добавить исключение (файл не правился). Затронуто: §3.4, Р16.
- **В6 → доходы и «Накопления» считаются, «—» только без данных.** Решение: строки не прочёркиваются целиком; «—» — когда нет сумм в обоих периодах. Затронуто: §5.7. Порождён новый вопрос В12 (цвет).
- **В2 (часть Δ) → формат Δ.** Решение: целые рубли, минус U+2212, пробел перед «%»: «+12 %», «−21 %». Интерпретация ответа «минус с пробелом» — см. §5.6 (при иной трактовке меняется только форматтер). Формат сумм в ячейках периодов (копейки, знак минуса) остаётся в вопросе В2 и вне рамок задачи сравнения. Затронуто: §5.6, Р8.
- **В1 → заголовок страницы не добавляем.**

- **Все [предложение] подтверждены**, в т.ч.: колонки Δ только при ≥ 2 периодах; подписи «Δ, ₽»/«Δ, %», периоды — в подписи под таблицей; формат «−21 %» (минус U+2212, NBSP перед «%»); ручная смена дат сбрасывает быстрый период; «Нет данных», если у всех узлов нет сумм; выбранная ячейка — 600.
