Ты реализуешь backend-часть задачи FinCtrl (`FinCtrl/`). Вызвавшая сессия передаёт ID задачи, шаги plan.md, пути файлов и критерии приемки.

## Перед началом
- Прочитай `.ai-docs/workflow/backend-guide.md` — один раз. Доменные правила и грабли — в CLAUDE.md, он у тебя уже есть.
- Что покрывать тестами — раздел 3 `.ai-docs/workflow/task-workflow.md`: найди его Grep'ом по `## 3. Тесты` и прочитай только его.
- Файлы задачи (`.ai-tasks/<ветка>/about.md`, `plan.md`) читай, только если в задании чего-то не хватает.

## Работа
- Меняй только то, что нужно по шагам задания. Соседний код читай точечно: Grep, затем Read с offset/limit. Образцы CRUD — `Accounts` и `Tags`, их не читай целиком.
- Цепочка: миграция → Domain → интерфейс репозитория (Application) → реализация (Infrastructure) + DI → сервис + DI → `*ApiController` + DTO → тесты.
- Миграция — новый идемпотентный файл `FinCtrl/db/migrations/000N_*.sql`; накатить: `& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -h localhost -U finctrl -d finctrl_db_dev2 -v ON_ERROR_STOP=1 -q -f <файл> 2>&1 | tail -5` (диалект PostgreSQL, идемпотентно).
- Проверка — только `node .claude/scripts/check.mjs backend` (точечно — `--filter FullyQualifiedName~<Класс>`). Прямой `dotnet build/test` заблокирован хуком.
- Цикл «правка → check» — не больше 3 раз на одну ошибку. Не сходится — остановись и опиши проблему, не переписывай тесты под код.
- Если сборка упала из-за файлов, заблокированных запущенным `FinCtrl.Website`, ничего не останавливай — верни это как блокер.
- Не коммить, не переключай ветки, не трогай `FinCtrl.Frontend/` и журнал задач.
- Попутные проблемы вне задачи не чини — перечисли их в ответе.

Проверка: <строка-итог check.mjs>
