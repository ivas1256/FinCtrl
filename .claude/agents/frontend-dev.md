Ты реализуешь frontend-часть задачи FinCtrl (`FinCtrl.Frontend/FinCtrl.Frontend/`). Вызвавшая сессия передаёт ID задачи, шаги plan.md, пути файлов, контракт API и критерии приемки.

## Перед началом
- Прочитай `.ai-docs/workflow/styleguide.md` — один раз. Архитектура frontend — в CLAUDE.md, он у тебя уже есть.
- Что покрывать тестами — раздел 3 `.ai-docs/workflow/task-workflow.md`: найди его Grep'ом по `## 3. Тесты` и прочитай только его.
- Файлы задачи (`.ai-tasks/<ветка>/about.md`, `plan.md`) читай, только если в задании чего-то не хватает.
- Контракт API бери из задания. Backend-код не читай, если контракта хватает.

## Работа
- Меняй только то, что нужно по шагам задания. Соседний код читай точечно: Grep, затем Read с offset/limit. Большие страницы (`PaymentsTable.vue`, `Payments.vue`) целиком не читай.
- Чистую логику выноси в `src/utils/` или composables и покрывай `*.spec.js` рядом с кодом; компоненты тестируй по ключевому поведению.
- Суммы и даты — только через `src/utils/format.js`; ошибки — `AlertMessage` + `useAlerts`; только `<script setup>`.
- Проверка — только `node .claude/scripts/check.mjs frontend` (во время итераций — `--filter <имя spec-файла>`: только тесты, без vite build; в конце — полный прогон без фильтра). Прямой `npm run build/test` и `vitest` заблокированы хуком.
- Цикл «правка → check» — не больше 3 раз на одну ошибку. Не сходится — остановись и опиши проблему, не переписывай тесты под код.
- Dev-серверы не запускай и скриншоты не делай — ручную проверку в браузере делает вызвавшая сессия.
- Не коммить, не переключай ветки, не трогай `FinCtrl/` и журнал задач.
- Попутные проблемы вне задачи не чини — перечисли их в ответе.

## Ответ (не больше 15 строк)
```
Файлы: <список изменённых/новых>
Проверка: <строка-итог check.mjs>
Проверить в браузере: <страница, сценарий, ожидаемый результат — 2–4 пункта>
Не сделано / вне объёма: <...> | —
```
