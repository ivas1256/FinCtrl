# Миграции БД

Просто папка с SQL-файлами, без ORM и без раннера. Никакой автоматической
таблицы учёта применённых миграций нет — что применено, видно по названию
файла и истории git/чата с остальными разработчиками.

## Соглашение об именовании

```
000N_короткое_описание.sql
```

Номер — сквозной, по порядку. Следующий файл после `0001_initial.sql` —
`0002_....sql`, и так далее. Не переиспользовать номера и не менять задним
числом уже применённые файлы — вместо правки старого файла добавляется новый.

## Файлы

- `0001_initial.sql` — структура БД `FinCtrl_db_dev2` по состоянию на
  2026-09-08 (Categories, PaymentSources, Payments: таблицы, PK/FK, индексы,
  default-constraints). На саму dev2 этот файл накатывать не нужно — она уже
  в этом состоянии. Нужен, чтобы поднять БД с нуля (новое окружение, чистая
  dev/test-база) и как точка отсчёта для следующих миграций.
- `0002_accounts.sql` — таблица `Accounts` (счета: `ExcelAccountName` —
  название в исходном файле банка, `DisplayName` — отображаемое название) и
  колонка `Payments.AccountId` (FK на `Accounts`). Нужно накатить на dev2.
- `0003_tags.sql` — таблица `Tags` (уникальное `TagName`) и связка
  `PaymentTags` (many-to-many платежей и тегов, без каскадного удаления —
  приложение само удаляет связи перед удалением тега). Нужно накатить на dev2.

## Как накатить

Вручную через sqlcmd (или аналогично через SSMS/Azure Data Studio):

```powershell
sqlcmd -S <сервер> -d <база> -E -C -i db\migrations\0001_initial.sql
```

`-E` — Windows-аутентификация (как в текущих строках подключения), `-C` —
доверять сертификату сервера. Для следующих миграций — та же команда с новым
файлом, по порядку номеров.
- `0004_payment_source_classification.sql` — колонки `PaymentSources.Classification`
  (классификация источника, `NVARCHAR(200) NULL`) и `PaymentSources.IsAiClassified`
  (`BIT NOT NULL DEFAULT 0`: классификацию проставила LLM, ручная правка
  сбрасывает флаг). Идемпотентна. Нужно накатить на dev2.
